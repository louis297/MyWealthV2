# Glossary

Shared words for MyWealthV2. When a Feature Spec or domain doc introduces a new term, add it here in the same change.

If another document disagrees with this file, this file wins and the other document is updated.

Phase-2 ledger words are kept so names stay stable. They are **not** Phase-1 schema or API.

---

## Product / domain

| Term | Meaning | Not |
| --- | --- | --- |
| MyWealthV2 | This wealth-management SaaS. | — |
| Tenant / Firm / Client | A contracted firm on the platform. One firm = one tenant. | End-client **Customer** |
| TenantCode | Login identifier for a tenant. Phase 1 uses a code; no subdomain routing. | `TenantId` (internal integer key) |
| User | A person in the domain. All five roles share one Domain `Users` table (`SimulatorOperator` is the fifth, [ADR 0021](adr/0021-outside-parties-behind-ports.md)). | The ASP.NET Identity login row by itself |
| SystemAdmin | Platform-level operator. Not bound to a tenant. Signs in to Back Office only. | TenantAdmin |
| TenantAdmin | Highest authority inside one tenant. | SystemAdmin |
| Adviser | Tenant operator who manages assigned customers (and, from Phase 2, their ledger). | Customer |
| Customer | Account holder. Login principal. Phase 1 client `adviser-portal` issues no code. Client `customer-portal` is accepted ([customer-portal/customer-portal.md](customer-portal/customer-portal.md)). | A business row with no login principal |
| SimulatorOperator | Fifth role ([ADR 0021](adr/0021-outside-parties-behind-ports.md), accepted: [features/simulator.md](features/simulator.md)). Platform-level like SystemAdmin: no tenant, no adviser. Signs in only on client `simulator`. No permission; `webapi` answers 401 to its token. | SystemAdmin; an operations role inside a tenant (roadmap D5) |
| Report | Platform catalog entry: PublicId, stable Code, name, function, scope (`Customer`, `Book` or `Tenant`), allowed triggers, IsActive. Disable cascades revoke of all TenantReports. | A tenant-owned row; a generated file |
| Book | An Adviser’s set of assigned Customers. Book-scoped reports run across that set. TenantAdmin selects an Adviser. | The whole tenant (a Tenant-scoped report); a single Customer |
| Tenant-scoped report | A report that runs across the whole Tenant (scope `Tenant`, beside `Customer` and `Book`), for TenantAdmin only: policies `reports.tenant.read` and `reports.tenant.create`. The first is `bank-reconciliation`. Accepted: [features/bank-reconciliation.md](features/bank-reconciliation.md). | A Book-scoped report (one Adviser's Customers); a platform-wide report |
| TenantReport | Grant of a Report to a Tenant. Required before the tenant can schedule or run it. | An execution |
| ReportSchedule | Editable recurring definition. Must name a ReportId. Stores a free-form `parameters` JSON object. | A one-off manual request |
| IReportGenerator | Per-report strategy. Registered by ReportId. Binds and validates `parameters`, checks scope, generates the result. | A Hangfire job type per report |
| asOf | Server-written UTC timestamp on Adviser Balances Report, set when the job is created. Not a client parameter. | A date the caller sends |
| Worker | Aspire resource `worker` (`src/Worker`). General-purpose Hangfire host for async tasks. | A second resource API |
| ApplicationUser / Identity user | ASP.NET Identity user in Infrastructure. All five roles share this table set. | Domain `User` |
| Permission / Policy | Named capability on an endpoint (for example `accounts.close`). Role → permission is mapped in code. | Per-tenant custom role tables; `AspNetRoles` |
| UserStatus | `PendingActivation` / `Active` / `Disabled`. Source of truth for a person. | Writing `IsActive` by itself |
| User.IsActive | Derived filter bit. `1` only when `Status = Active`. `PendingActivation` and `Disabled` are `0`. | A second writable switch; replacing `UserStatus` |
| Invitation | Admin does not set a password. Invitee sets a password via a one-time link. | Passing a password on the create API (Phase-1 transition path) |
| UserToken | One-time credential for invite / reset (hash only stored). Phase 1 reserves the table; no invite flow. | JWT access token |
| Account | Value container under a Customer (bank, cash, brokerage, property, liability, …). Phase 2. | An Identity login |
| Account.Currency | Currency of that account’s cash ledger. Immutable after open. | Instrument quote currency; tenant reporting currency |
| Account.Type | Capability gate on the container. Immutable after open. Phase 2 selectable: Bank, Cash, Brokerage, Other. | A product module; a stand-in that uses Other for Property or Credit |
| Custody mode | `Account.CustodyMode`: who holds the assets of an Account, and so where its numbers come from. `External` or `Custodial`. Set at open, immutable. Independent of `Account.Type`. ADR 0020; [features/account-custody-mode.md](features/account-custody-mode.md). | `Account.Type`; a setting on the Tenant; "book type" (Book is an Adviser's set of Customers) |
| External account | An Account with custody mode `External`. The assets are held outside the platform; the platform records what happened elsewhere, with numbers the caller supplies. Every Account opened before script `0031` is External. | An account the platform has a data connection to; the off-books counterparty of a `TransferIn` / `TransferOut`; a Closed account |
| Custodial account | An Account with custody mode `Custodial`. The assets are held by the platform and the platform executes the trades, so the platform's ledger is the authoritative record. Rules: [features/custody-modes.md](features/custody-modes.md) (a Custodial account is a `Brokerage` account, the server sets its `bookedAt`, and only it may follow a portfolio). | A `Brokerage` account (that is the type); a legal structure such as individual, joint or trust |
| Manual entry matrix | The table of which `TransactionType` a caller may enter on an Account of each custody mode, through a create route or reverse. One Domain function holds it. It does not apply to Transactions the platform builds itself (rebalance, the test seed, later platform-side flows). [features/custody-modes.md](features/custody-modes.md) §4.2. | The portfolio trade lock (that depends on an Active assignment, not on the custody mode); `Account.Type` as the capability gate for holdings |
| Allowed custody modes | The custody modes a Tenant's new Accounts may be opened with: `External`, `Custodial` or both, never none. Set by SystemAdmin. Checked only when an account is opened; narrowing it changes no existing account. [features/tenant-custody-modes.md](features/tenant-custody-modes.md). | A tenant type (ADR 0020 rejected it); the custody mode of an Account; a switch for the Custodial rules |
| Client money account | The trust bank account a firm holds Customers' cash in, one per Tenant and currency: bank name, account name and the full account number. Set by SystemAdmin, never edited (disable and add a new one). At most one active per currency. A Custodial account can be opened only in a currency that has an active one. Accepted: [features/client-money-accounts.md](features/client-money-accounts.md). | A Customer's own bank account (the nominated bank account, later); an `Account` of type `Bank`; a suspense account |
| Deposit reference | The code a Customer quotes when paying into the client money account, so the payment can be matched to one Custodial account. Nine characters from `0123456789ABCDEFGHJKMNPQRSTVWXYZ`, the first a letter, the last a Luhn mod 32 check symbol. Generated by the server when a Custodial account is opened; unique on the platform; never changed or reused. `depositReference` on the account item. Accepted: [features/client-money-accounts.md](features/client-money-accounts.md). | `Transactions.Reference` (free text on one Transaction); the account `PublicId` |
| Deposit instructions | Where and how to pay into a Custodial account: the active client money account in the account's currency plus the account's deposit reference. `GET /accounts/{id}/deposit-instructions`; available only for an Open Custodial account whose currency has an active client money account. Accepted: [features/client-money-accounts.md](features/client-money-accounts.md). | A deposit (the `TransferIn` that books the money); a payment instruction (a withdrawal, later) |
| Bank connection | A named entry in configuration (`BankConnections:{name}`) that says how the platform reads one bank: its adapter (`Simulator` first) and, on `worker` only, the address and key. Each client money account names its connection; it never changes. Accepted: [features/deposit-matching.md](features/deposit-matching.md). | A row in a table; the client money account itself; a Tenant setting |
| Bank statement line | One line of a client money account's bank statement, read through the bank feed and stored once per (connection, outside id) before any flow uses it: value date, direction, amount, payer (account masked) and reference text. Status `Received`, `Matched`, `Unmatched`, `Ignored`, `ReturnRequested`, `ReturnSent` or `Returned`. `/statement-lines`. The bank's inbound record (ADR 0021). Accepted: [features/deposit-matching.md](features/deposit-matching.md), [features/bank-returns.md](features/bank-returns.md). | A Transaction; a cash leg; a line in the simulator's own books |
| Deposit | Money a Customer paid into the client money account, posted to a Custodial account from a matched bank statement line: a `TransferIn` with source `BankFeed` (the line's PublicId as source id) and a bank receipt detail. Undone only by its flow (undo match), never by a hand reverse. Accepted: [features/deposit-matching.md](features/deposit-matching.md). | A hand-entered `TransferIn` (refused on a Custodial account from this slice; still the External way); deposit instructions |
| Bank receipt detail | The bank's data on a deposit: value date, reference text, payer name, masked payer account. Stored 0..1 per Transaction in `TransactionBankReceiptDetails`, copied to the Reversal; `bankReceipt` on the transaction item. Accepted: [features/deposit-matching.md](features/deposit-matching.md). | The statement line itself; `Transactions.Reference` |
| Suspense | The bank statement lines a TenantAdmin still has to decide on: `Unmatched` lines, which the platform could not place: receipts, and debit lines it did not cause or a recall the cash no longer covers. They are not in the ledger (roadmap D7). The TenantAdmin matches a receipt to a Custodial account, ignores it, or marks it for return; a debit line can only be ignored. Permission `statement-lines.manage`. Accepted: [features/deposit-matching.md](features/deposit-matching.md), [features/bank-returns.md](features/bank-returns.md). | A suspense account in the ledger; an `Account` |
| Nominated bank account | A Customer's own bank account that withdrawals may be paid to: bank name, account name, full account number and currency. Added by an Adviser or TenantAdmin, verified or rejected by a TenantAdmin other than the person who added it, removed with a note; the details never change. Status `Pending`, `Verified`, `Rejected` or `Removed`. `/nominated-bank-accounts`. Accepted: [features/withdrawals.md](features/withdrawals.md). | A client money account (the firm's trust account); an `Account` of type `Bank`; the payer account on a statement line |
| Withdrawal | An instruction to pay cash from a Custodial account to a verified nominated bank account of the same Customer, in the account's currency. Requested by an Adviser or TenantAdmin, approved by a TenantAdmin other than the requester, sent to the bank by the `worker`. Status `Requested`, `Approved`, `Sent`, `Paid`, `Rejected`, `Cancelled`, `Failed` or `Returned`. Not a Transaction; its payout is. `/withdrawals`. Accepted: [features/withdrawals.md](features/withdrawals.md). | A `TransferOut` (the payout, or a hand entry on an External account); a receipt return |
| Payout | The `TransferOut` the platform posts on a Custodial account when the bank statement shows a withdrawal's payment: source `Payment` with the withdrawal's PublicId, and a payment detail. Undone only by its flow (a returned payout), never by a hand reverse. Accepted: [features/withdrawals.md](features/withdrawals.md). | The withdrawal itself; a hand-entered `TransferOut` |
| Payment detail | The bank's data on a payout: value date, the reference sent, payee name, masked payee account. Stored 0..1 per Transaction in `TransactionPaymentDetails`, copied to the Reversal; `payment` on the transaction item. Accepted: [features/withdrawals.md](features/withdrawals.md). | The bank receipt detail of a deposit; the outgoing payment record |
| Reserved cash | The sum of a Custodial account's open withdrawals (`Requested`, `Approved`, `Sent`). It does not change the cash balance. `reservedCash` on the account item; always 0 on an External account. Accepted: [features/withdrawals.md](features/withdrawals.md). | A cash leg; a hold at the bank |
| Available cash | Cash balance minus reserved cash. Every write that lowers cash on a Custodial account must keep it `≥ 0`, except a payout, which releases its own reservation. `availableCash` on the account item. Accepted: [features/withdrawals.md](features/withdrawals.md). | Cash balance (the cash `SUM`); settled cash (later, roadmap O2) |
| Outgoing payment | One payment the platform asks a bank to make from a client money account, for a withdrawal or, from [features/bank-returns.md](features/bank-returns.md), a receipt return: an instruction id as its idempotency key (the withdrawal's PublicId, or the return payment's own), amount, payee or the line returned, status (`Pending`, `Accepted`, `Rejected`, `Cancelled`, `Paid`, `Returned`), send attempts, last failure and the bank's payment id. Sent by the bank sync job of its connection; no HTTP route of its own. Accepted: [features/withdrawals.md](features/withdrawals.md), [features/bank-returns.md](features/bank-returns.md). | A Transaction; a withdrawal (the instruction it pays) |
| Receipt return | Sending an unmatched receipt back to the payer: a TenantAdmin requests the return on the statement line, the `worker` sends an outgoing payment that names the line, and the line becomes `ReturnSent` when the bank accepts it and `Returned` when the bank's debit line shows it. Nothing is written to the ledger. Accepted: [features/bank-returns.md](features/bank-returns.md). | A recall; a returned payment |
| Recall | A debit line on which the payer's bank takes back a receipt it sent earlier (a recall or dishonour), naming that receipt's line. A matched receipt's deposit is reversed by the flow while the available cash allows; otherwise the line waits in suspense (`RecallNotCovered`) for an adjustment. Accepted: [features/bank-returns.md](features/bank-returns.md). | A receipt return (the firm sends the money back); undo match |
| Statement balance | The bank's balance of a client money account after the last statement line up to a feed cursor, sent by the bank with every page of the bank feed and stored on the cursor in the same transaction as the lines it covers. The bank figure of a bank reconciliation. Accepted: [features/bank-reconciliation.md](features/bank-reconciliation.md). | A balance the platform computes from its lines; the bank's balance by value date; a Custodial account's cash balance |
| Opening balance | The money in a client money account before the first statement line the platform holds for it: the first statement balance stored on its cursor minus the lines stored so far. Set once, never changed. Accepted: [features/bank-reconciliation.md](features/bank-reconciliation.md). | An `Opening` Transaction; a balance the firm types in |
| Bank reconciliation | One stored run that compares the statement balance of one client money account with the cash of every Custodial account of the Tenant in its currency, at one instant, and lists the reconciliation items that explain the difference. Status `Agreed` (no break), `Breaks` or `NoBankBalance`. Daily for every active client money account, or "Run now" by a TenantAdmin; never edited. Permission `bank-reconciliations.manage`. `/bank-reconciliations`. Accepted: [features/bank-reconciliation.md](features/bank-reconciliation.md). | A custodian (position) reconciliation (roadmap T3); a correction; the Bank receipts pages |
| Reconciliation item | One amount in a bank reconciliation that explains part of the difference between the bank and the platform: a statement line in suspense, not processed, being returned or ignored; cash on Custodial accounts that never passed through the trust account (trades, FX conversions, adjustments, other cash, another client money account); the opening balance; a statement difference; or what is left unexplained. Its amount is its effect on bank minus platform; the items of a run add up to the difference. Each kind has one class: break, timing or known difference. Accepted: [features/bank-reconciliation.md](features/bank-reconciliation.md). | A statement line; a Transaction; something a person edits |
| Break | A reconciliation item someone must act on: a statement line in suspense, a statement difference, or an unexplained difference. Fixed only by its cause (a flow or an adjustment); it is gone from the next run. A run with none is `Agreed`. Accepted: [features/bank-reconciliation.md](features/bank-reconciliation.md). | A row with its own status; a timing difference; a known difference |
| Timing difference | A reconciliation item that clears by itself: a statement line not processed yet, or a receipt being returned to its payer. Accepted: [features/bank-reconciliation.md](features/bank-reconciliation.md). | A break; a payment sent but not yet on the statement (no item: neither side has moved) |
| Known difference | A reconciliation item that is explained and accepted: an ignored statement line (with its note), the opening balance, cash from another client money account, and Custodial cash that never passed through the trust account (trades and FX conversions until roadmap O1, O2, O5; adjustments; other cash entered on the platform). Accepted: [features/bank-reconciliation.md](features/bank-reconciliation.md). | A break; a timing difference |
| Account closure | The flow that closes a Custodial account: requested by an Adviser or TenantAdmin with a memo, for an account with no holding, no Active portfolio assignment and no open withdrawal. The cash balance rounded down to the minor unit is paid out as an ordinary withdrawal created with the closure; when its payout posts, the remainder write-off and the close follow in the same database transaction. With nothing to pay out it completes at once. Status `InProgress`, `Completed` or `Cancelled` (it ends with its withdrawal). `/accounts/{accountId}/closures`. Accepted: [features/account-closure.md](features/account-closure.md). | `POST /accounts/{id}/close` (the plain close, External accounts only from this slice); a withdrawal; offboarding a Customer |
| Closing account | A Custodial account with an account closure `InProgress`. It accepts no hand write and no portfolio assignment; a receipt or returned payout for it waits in suspense with reason `AccountClosing`. Accepted: [features/account-closure.md](features/account-closure.md). | A Closed account; an account with reserved cash |
| Remainder write-off | The `CloseOut` an account closure posts for the part of a Custodial account's cash below the currency's minor unit (left by a trade's cash leg rounded to 4 decimals), source `AccountClosure`, so the cash is exactly 0 when the account closes. Never entered or reversed by hand. Accepted: [features/account-closure.md](features/account-closure.md). | A hand `CloseOut`; an `Adjustment` |
| Tax profile | A Customer's three tax attributes: tax residency (`NewZealand` or `Overseas`), whether the firm holds the Customer's IRD number, and the RWT rate the Customer chose (10.5, 17.5, 30, 33 or 39 %, or none). Set by an Adviser or TenantAdmin, read by the Customer; a Customer with nothing saved is "not provided". The IRD number itself is not stored. It decides the withholding tax when interest is paid. `/users/customers/{customerId}/tax-profile`. Accepted: [features/interest-run.md](features/interest-run.md). | A KYC record; the IRD number; a tax return |
| Withholding tax | Tax the platform takes from income when it pays it, booked as a `Tax` cash leg: RWT (resident withholding tax) for a New Zealand resident at the chosen rate, 33 % with no rate chosen, or 45 % when no IRD number is held; NRWT (non-resident withholding tax) at 15 % for an overseas Customer. Decided from the tax profile at the moment of the posting. Accepted: [features/interest-run.md](features/interest-run.md). | Income tax the Customer files; a trade fee; a foreign tax a dividend arrives net of (later) |
| Tax detail | How one `Tax` cash leg was computed: tax kind (`Rwt`, `Nrwt`), rate percent, basis amount (the gross), tax amount and currency. Exactly one per `Tax` leg in `TransactionTaxDetails`, copied to the Reversal's matching leg. Dividends reuse it. Accepted: [features/interest-run.md](features/interest-run.md). | The `Tax` cash leg itself; the fee detail; the tax profile |
| Interest rate schedule | Tenant row per cash currency, effective from a date: marginal bands of annual rates that Custodial cash earns. In effect once its date is on or before the cut-off date (the later of today and the last day any account in the currency was accrued through), then never changed; pending before that. `/interest/rate-schedules`. Accepted: [features/interest-run.md](features/interest-run.md). | A trade fee schedule; the rate the bank pays on the trust account; a per-Customer rate |
| Day balance | A Custodial account's closing cash balance of one UTC day: the sum of its cash legs booked before the next day starts. The amount a daily accrual is computed on; reserved cash counts. Accepted: [features/interest-run.md](features/interest-run.md). | Available cash; the cash balance now; a balance by the bank's value date |
| Daily accrual | The interest one Custodial account earned on one UTC day: the applicable schedule's bands applied to the day balance, divided by 365, kept to 8 decimals. Stored once per account and day in `InterestAccruals`, never changed, and stamped with the Transaction that pays it. `GET /accounts/{accountId}/interest-accruals`. Accepted: [features/interest-run.md](features/interest-run.md). | A cash leg (an accrual is not in the ledger until it is posted); the interest posting |
| Interest posting | The `Interest` Transaction that pays an account's unposted daily accruals after a calendar month: a `Principal` cash leg of the gross (the accruals rounded to the minor unit), a `Tax` cash leg of the withholding tax, an interest detail and a tax detail, source `InterestRun`. Never entered or reversed by hand. Accepted: [features/interest-run.md](features/interest-run.md). | A hand-entered `Interest` on an External account; a daily accrual |
| Interest detail | The period of an interest posting: first and last day paid, number of days, the accrued amount (8 decimals) and the gross. Stored 0..1 per Transaction in `TransactionInterestDetails`; `interest` on the transaction item. Accepted: [features/interest-run.md](features/interest-run.md). | The daily accrual rows; the tax detail |
| Interest run | One stored execution of the interest work for one Tenant and one as-of date: every Open Custodial account is accrued through that day, and the months that ended by it are posted. Daily by the `worker` for yesterday, started by a SystemAdmin for a date, or for one account when an account closure pays its final interest. The source of the Transactions it posts. `/interest/runs`. Accepted: [features/interest-run.md](features/interest-run.md). | A bank reconciliation run; a rebalance; one account's posting |
| Bank interest | Interest the bank pays on a client money account itself: a bank statement line of kind `Interest`. The platform sets it aside (`Ignored`, note `Bank interest`) and posts nothing; the bank reconciliation lists it as the known difference `BankInterest`, next to `InterestCredited` and `TaxWithheld`. Accepted: [features/interest-run.md](features/interest-run.md). | The interest Customers earn (posted by the interest run from the Tenant's schedule); a deposit |
| Corporate action | An event of one Instrument of one Tenant that changes the quantity of every holding of it on the Tenant's Custodial accounts by one factor and leaves each holding's total cost as it is: a `Split`, a `Consolidation` or a `Bonus`, with a ratio of two whole numbers ("2 for 1") and an ex-date, record date and payment date. Origin `Feed` (from a corporate action announcement) or `Manual` (entered by a TenantAdmin); status `Announced`, `Effective`, `Applied` or `Cancelled`. A person enters the event, never a quantity. `/corporate-actions`. In review: [features/corporate-actions.md](features/corporate-actions.md). | A hand-entered `Split` / `Bonus` / `Scrip` on an External account (the caller sends the new total quantity); a dividend (later); an adjustment |
| Corporate action announcement | One version of one event at an outside party, read through the corporate action feed and stored once per (connection, outside id) before any flow uses it: the party's action id, version, status (`Announced`, `Effective`, `Cancelled`), symbol, currency, kind, ratio and dates. Platform data with no Tenant; processing turns it into a corporate action on every Tenant's instrument with that symbol and quote currency, or skips it with a reason. The issuer's inbound record (ADR 0021). In review: [features/corporate-actions.md](features/corporate-actions.md). | The corporate action itself (a Tenant's row); a statement line |
| Entitlement | What one Custodial account gets from one corporate action: stored `Pending` for every account that holds the instrument when the action takes effect, then posted once as a `Split` or `Bonus` Transaction with the quantity before and after, or `NotApplied` (`NoHolding`, `TooSmall`). At most one per corporate action and account. In review: [features/corporate-actions.md](features/corporate-actions.md). | The Transaction it posts; a right the holder must elect (not modelled) |
| Corporate action detail | The event behind an entitlement posting: kind, ratio, ex-date, record date, payment date, quantity before and quantity after. Stored 0..1 per Transaction in `TransactionCorporateActionDetails`, copied to a Reversal; `corporateAction` on the transaction item. In review: [features/corporate-actions.md](features/corporate-actions.md). | The corporate action row; the security leg (it holds only the difference) |
| Executed price | The price per unit, in the instrument's quote currency, at which an outside broker filled a `Buy` or `Sell` on an External account. Sent by the caller as `security[0].price`; the trade's gross amount is quantity × executed price. Not stored on the leg. [features/external-caller-numbers.md](features/external-caller-numbers.md). | A close price in `InstrumentPrices`; a price override on a Custodial account (refused) |
| Funds under management (FUM) | The cash and holding market value of the Open Custodial accounts in a scope (the firm, an Adviser's Customers, one Customer), per currency, with no FX fold. The `Custodial` entry of the net-worth breakdown `byCustodyMode`. The later base of the advisory fee and platform billing. [features/custody-mode-grouping.md](features/custody-mode-grouping.md). | Net worth (it also counts External accounts); assets under advice; a figure folded into one currency |
| External assets | The cash and holding market value of the Open External accounts in a scope, per currency. The `External` entry of `byCustodyMode`. The Customer Portal calls them "Held elsewhere" and notes that the platform has not checked them. [features/custody-mode-grouping.md](features/custody-mode-grouping.md). | Funds under management; a valuation-only record of property or loans |
| AccountStatus | `Open` / `Closed`. Source of truth for an account. HTTP close / reopen. | Instrument disable; `UserStatus` |
| Account.IsActive | Derived filter bit. `1` iff `Status = Open`. Inactive accounts drop out of later net worth. | A writable body field; `IsEnabled` |
| Cash ledger | Cash entries and balance in the account’s booking currency. Phase 2. Owned by the posting spec, not a separate Feature Spec. | Holding quantity |
| Cash balance | `SUM` of posted cash-leg signed amounts on one Account. Computed. Not a column on `Accounts`. | A persisted `Account.Balance`; net worth |
| Holding | Position of one instrument inside an account (quantity + cost). Phase 2. | A single transaction |
| Portfolio | Target-weight model of instruments with a mandatory base currency. Accepted. An Adviser assigns at most one Active portfolio to a Brokerage or Other account. | A new Account.Type; a free-form basket |
| AccountPortfolioAssignment | Link that binds one Account to one Active Portfolio. Accepted. While Active, manual security trades are rejected. | A second holdings book |
| Shared portfolio | A Portfolio with at least one Active assignment on an Account outside the calling Adviser's Book. An Adviser cannot update or disable it (409 `portfolio_shared`); a TenantAdmin can. Defined per caller, not stored. See [features/portfolios.md](features/portfolios.md), amendment 2026-11-13. | A portfolio with an owner; a cross-tenant portfolio |
| Problem code | Stable snake_case `code` on a `webapi` error body that names the meaning of a refusal (`stale_row_version`, `portfolio_shared`). Every 409 and every named business 400 has one. Clients branch on it, not on the status alone. The registry is [api-design.md](api-design.md) §4.2. | The HTTP status; a field-validation message in `errors`; a custom `type` URI |
| Instrument | Holdable object from an in-database catalog. Phase 2. | A free-text name stored on Holding |
| Symbol | Instrument code on the tenant catalog (ticker-style unique key inside one tenant). | Display `Name`; ISIN |
| QuoteCurrency | Currency used for the instrument’s price, market data, and cost accumulation. | Account booking currency |
| CostBasis | Holding cost as `Money`. Currency must equal the instrument quote currency. | Market value |
| Opening / initial holding | The only entry that may write quantity and cost directly. Phase 2. | Day-to-day holding edits |

| Standing account | A simulator bank account listed in the simulator's configuration (`Simulator:Bank:StandingAccounts`), opened when the simulator world is created and again after every reset, so the trust accounts the platform reads survive a reset. Accepted: [features/deposit-matching.md](features/deposit-matching.md). | A client money account on the platform; an account opened by a control call |
| Market data connection | A named entry in configuration (`MarketDataConnections:{name}`) that says how the platform reads one market data party: its adapter (`Simulator` first), a symbol suffix (for example `.SIM`) and, on `worker` only, the address and key. It serves every Instrument whose symbol ends with its suffix: their prices come from it and not from EODHD. `GET /market-data-connections`. Accepted: [features/simulated-instruments.md](features/simulated-instruments.md). That their corporate actions also come from it, and not from hand entry, is in review: [features/corporate-actions.md](features/corporate-actions.md). | A bank connection; a row in a table; EODHD (not behind a connection) |
| Market prices | The port (`IMarketPrices`) through which the `worker` reads the current price of every instrument a market data connection serves, in one call on the connection's polling interval. Each price is stored in `InstrumentPrices` under the platform's UTC date. Accepted: [features/simulated-instruments.md](features/simulated-instruments.md). | `IMarketData` (the read port over the local table); `IInstrumentPriceSource` (EODHD, one symbol per call) |
| Corporate action feed | The port (`ICorporateActionFeed`) through which the `worker` reads the corporate action announcements of one market data connection after its feed cursor, in the connection's job and before its price read. In review: [features/corporate-actions.md](features/corporate-actions.md). | A push from an issuer; the hand entry of a corporate action |
| Simulator market | The simulator party that plays the issuer and the data vendor of its own instruments: it holds the simulated instruments and their prices, and announces, amends and cancels their corporate actions. Routes under `/party/market` and `/control/market`. Instruments and prices accepted: [features/simulated-instruments.md](features/simulated-instruments.md). Corporate actions in review: [features/corporate-actions.md](features/corporate-actions.md). | The simulator bank; a real exchange; the platform's instrument catalog |
| Simulated instrument | A made-up instrument the simulator market owns: a symbol ending in `.SIM`, a currency and one price per simulator day, moved by a seeded random step or set by the operator, and rebased when one of its corporate actions takes effect. A Tenant lists it in its catalog like any instrument; the platform prices it through the market data connection (roadmap D11). Accepted: [features/simulated-instruments.md](features/simulated-instruments.md); the rebase on a corporate action is in review in [features/corporate-actions.md](features/corporate-actions.md). | A real instrument priced by EODHD; a `TestSeed` instrument with a fixed price |
| Standing instrument | A simulated instrument listed in the simulator's configuration (`Simulator:Market:StandingInstruments`), added when the simulator world is created and again after every reset, so the instruments a Tenant already lists keep a price. Accepted: [features/simulated-instruments.md](features/simulated-instruments.md). | A catalog row on the platform; an instrument added by a control call |

## Account types (Phase 2 names; reserved)

| Value | Notes |
| --- | --- |
| Bank | Deposit-style cash at a bank: current / savings and similar. Not the bank as an institution. Phase 2 openable; cash book only; no holdings. |
| Cash | Physical or not-yet-banked cash. Phase 2 openable; cash book only; no holdings. |
| Brokerage | Equities, funds, ETFs, and similar positions. Phase 2 openable; may hold instruments. |
| Property | Real property held as instruments in this account. Reserved name; not selectable in Phase 2. |
| Credit | Cards and loans. Counts as a liability in net worth. Reserved name; not selectable in Phase 2. |
| Other | Catch-all. Phase 2 openable; may hold instruments. Not a substitute for Property or Credit. |

Account type does **not** replace the cash ledger. Cash balance comes from cash postings. Do not infer cash by branching on `AccountType == Bank` and summing transactions.

## Status of this glossary

- Product terms follow locked decisions as of 2026-09-11.
- Login context is **TenantCode** (Phase 1 does not parse a host subdomain).
- Session protocol is OpenIddict authorization code + PKCE (ADR 0014).
- Five roles share one Domain `Users` table and one `ApplicationUser` table (ADR 0013, amended by ADR 0021).
- Internal key is `int` identity; external key is `PublicId` (ADR 0007).
- Reversal and instrument catalog wording is reserved for the Phase-2 ledger. Phase 1 does not implement those tables or APIs.
- Invitation / password-reset wording is reserved. Phase 1 keeps `UserStatus`, `UserTokens`, and `IEmailSender` seams only.
